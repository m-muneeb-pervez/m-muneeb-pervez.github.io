Research

LLM agent security

Splitting a task across several agents changes where an attacker can strike. With safeMAS [3], I evaluate multi-agent LLM systems under adversarial manipulation across several architectures. Attack success depends on which agent is compromised, and attacks can also target the channels between agents. I am now studying internal threats, where an agent given a legitimate task and no external attacker reasons its way into a harmful, unsanctioned action. I want to know whether multi-agent architectures and tool partitioning change how often this happens and how much damage it causes.

Empirical and usable security

Much of my work is empirical. In [1], we paired the analysis of 50 apps with a user study. In [2], we benchmarked four frontier LLMs and two open-weight vision-language models on 2,843 videos from eight countries.

Privacy

In [1], 85% of participants did not understand basic app permissions, and the apps we studied exploit populations with limited literacy. We evaluated LLM-generated summaries, translations, and visual cues as privacy-literacy interventions that could scale.

Systems security

Coursework and projects in vulnerability analysis gave me a base in low-level security: building stack layouts and shellcode for buffer overflows, mapping control-flow hijack points in compiled binaries with GDB, and writing a parser that builds abstract syntax trees. I see this as groundwork for automated vulnerability detection and program analysis.
